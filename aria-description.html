Aria — Reconciliation Agent

A runnable Python project for exploring the Claude Sonnet 5.5 Messages API. Aria investigates a fictional month-end revenue mismatch, builds an evidence-backed correction plan, and earns write access only after Python validates it.

read-only tools python validator gate gated write access claude-sonnet-5-5

01 · The Fictional Scenario

October closes. The CRM and the General Ledger report different revenue figures. Aria's job is to find out why — using only read-only tools — then propose a correction plan precise enough to pass automated validation before any write is permitted.

CRM / Billing
$847,250
12 deals recorded
GL / Ledger
$821,500
11 entries posted
Unexplained delta — Aria must account for every dollar −$25,750

Hidden inside the data: one deal double-counted in the CRM, one deal missing from the GL, and one amount off by $4,250 from a data-entry rounding error. Aria discovers all three through tool calls, never through guessing.

02 · How Aria Works

The agent runs through three distinct phases. The permission gate between Phase 2 and Phase 3 is the core teaching point of the project.

1
Investigate — read-only tools only

Aria queries the CRM export, the GL ledger, and a comparison engine. It may call multiple tools in parallel. No writes of any kind are available at this stage.

2
Plan — structured correction proposal

Once the investigation is complete, Aria submits a CorrectionPlan: a structured object that names each discrepancy, cites the evidence, and states the corrective amounts.

✓
Python validates the plan

A deterministic validator checks the plan against rules: all discrepancies accounted for, amounts balance, required evidence fields present. If it fails, Aria is told why and must revise.

3
Write — gated access unlocked

Only after the validator passes are the write tools injected into the tool list: post_correction and write_report. Aria applies the corrections and produces a signed audit report.

04 · API Usage Pattern

Aria uses the @beta_tool decorator and the SDK's tool runner. The permission gate is ordinary Python — not an API feature — which keeps the pattern simple and portable.

aria/agent.py 
# Phase 1 + 2: read-only loop
runner = client.beta.messages.tool_runner(
    model="claude-sonnet-5-5",
    max_tokens=16000,
    tools=[query_crm, query_gl, compare_sources,
           get_summary, submit_plan],
    messages=[{"role": "user", "content": SYSTEM_PROMPT}],
)
for msg in runner:
    print_turn(msg)

# Gate: Python validates the plan Aria submitted
result = validator.validate(aria.correction_plan)
if not result.ok:
    # re-run with feedback — Aria revises
    ...

# Phase 3: inject write tools, complete the task
runner = client.beta.messages.tool_runner(
    model="claude-sonnet-5-5",
    max_tokens=8000,
    tools=[post_correction, write_report],
    messages=aria.history,
)

05 · What You Learn Running This

  • How to define tools with @beta_tool and let the SDK manage the agentic loop
  • How to use parallel tool calls — Aria queries CRM and GL simultaneously in one turn
  • How to implement a deterministic permission gate between investigation and action
  • How adaptive thinking works on Sonnet 5.5 — visible reasoning in the terminal
  • How to pass structured data between Claude and Python through validated tool schemas
  • How to build an audit trail: every correction references the tool result that justified it
